## 2. What Went Well

- **The library boundary held under pressure.** AD-2 protocol containment survived nine bugfixes' worth of
  churn. Every wire-format correction landed inside `aiosecurityspy`; none leaked into the integration.
  The architecture paid for itself precisely where it was designed to.
- **Corrections landed in the library, not in Home Assistant.** Nine bugfixes in a protocol library is a
  far cheaper number than nine bugfixes spread through entity code, coordinators, and config flows. The
  sequencing decision — library first — is validated by exactly the thing that looked like a cost.
- **The correction loop was fast and fully documented.** Live verification produced eight scoped stories in
  a single day, each with its own spec and regression test. Nothing was silently patched.
- **Automation halted correctly on an ordering error.** The dev-auto run for story 2.4 refused to proceed
  because 2.3 was unimplemented, rather than unilaterally inventing the permanent device-identity scheme.
  Halting was the right outcome and the system chose it.
- **The deferred-work ledger is a genuine asset.** Every entry records not only what was deferred but why
  it could not be resolved — usually "needs a live server" or "this is a spec-level decision, not a
  patch." That discipline is what made the August 29 verification session productive instead of
  exploratory.
- **Real progress against an undocumented API.** SecuritySpy's protocol was reverse-engineered from the
  running product. The team found the traps — CR-only framing, the overloaded `t` field, the split camera
  inventory — before they reached the integration.

## 3. Challenges and Growth Areas

### 3.1 HTML evidence showed shape, not values

Stories 1.1–1.7 were built against the research documents and the SecuritySpy web client's own HTML. That
was real evidence and it carried the work a long way — this was not a case of guessing. The gap was
narrower and more specific: **markup reveals the vocabulary, but not the wire values.**

What only appeared once real traffic was captured:

- A 401 from media endpoints can mean *permission denied*, not bad credentials (story 1.11, 1.14).
- `caplist.m` is a float in **megabytes**, not an integer byte count (story 1.15).
- `++camStatus` and `++systemInfo` enumerate **different camera sets** — a disabled camera vanishes from
  `systemInfo` but not `camStatus` (story 1.12).
- Event and capture times carry the server's **offset**, which is not a timezone (story 1.13).
- `t` means one thing in `caplist` and another in `clip` — the enums must not be shared.
- `mode` selects which capture modes a write targets (story 1.16).
- Permissions vary **per camera**, never collapsing to one account-level set.

Every one of these passed a green test suite beforehand, because the fixtures were authored to match the
assumption. The epic context now states the rule explicitly: *"Wire-shape correctness is verified against
captured real-server payloads (live 6.21 fixtures), not fixtures authored to match a guess."* That sentence
was written after the cost was paid.

**Jensen's read (accepted by the team):** the web code was reasonable evidence and a HAR file did not seem
necessary at the time. The correction going forward is to supply **both** — HTML for the vocabulary, HAR
for the values.

### 3.2 Epic 2 started before the library was verified

Stories 2.1 and 2.2 landed on August 16, thirteen days before live verification overturned eight library
assumptions. The concrete consequences now sitting in the ledger:

- `manifest.json` pins `aiosecurityspy==0.2.0`, a version not on PyPI. The integration's tests pass only
  because `[tool.uv.sources]` resolves the library to an editable local path — nothing in CI proves the
  pinned version is installable.
- DW-2 (delete the in-tree `aiosecurityspy/` subtree and consume the published package) is blocked behind
  that release.
- The integration has **no CI at all** — no pytest, no ruff, no mypy, no hassfest, no HACS Action. Only the
  library has workflows. No Epic 2 story owns creating them.

**Jensen's position, accepted:** the release is not a real blocker. The team owns `aiosecurityspy` and cuts
releases on demand; at 0.x.x there is no stability contract to negotiate. This is a command to run, not a
dependency to wait on.

## 4. Key Lessons

1. **HTML gives you the vocabulary; traffic gives you the values.** Both are required to decode an
   undocumented protocol. Neither alone is sufficient.
2. **A green test suite proves nothing about wire format when the fixtures encode the assumption.** Fixtures
   must be captured, not authored, for any decoding claim.
3. **The library-first sequencing was correct and is validated by the bugfix count.** Nine corrections
   inside a contained protocol boundary is the cheap version of this epic.
4. **Consumers should not be built against an unverified provider.** Epic 2 starting early is the source of
   every currently-open coupling problem.
5. **A deferred-work ledger that records *why* something was deferred converts a backlog into a work
   queue.** The August 29 session was productive because the ledger told it what to ask the server.

### Known Epic 2 loose ends already in the ledger

- `_abort_if_unique_id_configured()` discards a newly-entered address, so re-adding a server that moved
  (DHCP lease change) aborts while the entry keeps the dead host. Story 2.9 owns address changes; if 2.9
  ships only a reconfigure flow, this re-add path must be closed deliberately rather than by omission.
- `async_setup_entry` raises `ConfigEntryNotReady` / `ConfigEntryError` with no `message` and never logs

  decision to be made once for every clause.
- Certificate failures on the long-lived event stream fold into indefinite silent backoff. Belongs to the
  Epic 3 story that owns stream health reporting.
