- (decision) Stakes: public launch grade. HACS-distributed, third parties depend on it, Bronze in full / Silver on release, core submission kept possible. Drives full FR set + NFRs + quality-scale-as-requirement.
- (decision) Closes addendum §7 item 1 (PRD-blocking 'no concrete automation scenarios'): the two canonical scenarios are (a) retroactive query of the observation record from HA alone, correct after restart, and (b) narrated outdoor alerts - detection to image to vision model to human-readable notification. Arming-follows-presence and noise-tuning NOT selected as headline scenarios.
- (decision) Both selected scenarios are outdoor-focused and both depend on the image entity being reachable by a downstream consumer - reinforces observation record + image entity as the two load-bearing deliverables; arm switches and trigger switches are supporting, not headline.
- (decision) Working mode: Fast path. Inputs unusually complete; remaining gaps batched then full draft with [ASSUMPTION] tags.
- (decision) Closes addendum §7 item 4: image access is HA-proxied ONLY. Integration promises a stable HA-served image URL; makes NO promise about direct SecuritySpy network reachability. Avoids leaking topology and the credential-in-URL leak flagged in research. Works regardless of user network topology (does not assume a tailnet).
- (decision) v1 scope holds the brief's line: get_clip and media_source browser BOTH deferred to v2. Rationale: smaller surface reaches Bronze sooner; shipping is what the predecessor failed at. get_clip disk-fill caveat also avoided for v1.
- (decision) Closes addendum §7 item 9 (arming): arm switches write the OVERRIDE only, never the schedule - non-destructive, user's SecuritySpy schedules stay intact. PLUS schedule exposed as read-only visibility so users can see which schedule is active without HA being able to clobber it.
- (decision) Closes addendum §7 item 6 (tuning): classification confidence threshold + debounce ship with a GLOBAL default (~70pct, min consecutive frames) AND a per-camera override. Rationale: Jensen's indoor/outdoor split is exactly the case where one number cannot fit - indoor cams generate most classification traffic. Defaults marked provisional pending real-footage tuning.
- (decision) Closes addendum §7 item 9b (CoreML): Jensen chose FULL DYNAMIC ENTITY CREATION - discover custom model labels from the event stream and create binary sensors for them. This EXPANDS beyond the brief, which said 'integration will not use this in v1, but event parsing built to carry arbitrary labels from the start'. Supersedes that brief statement.
- (change) RISK on CoreML dynamic entities: research confirms the custom-model event payload shape is UNDOCUMENTED and 'must be discovered empirically' - the web client has zero CoreML references and the published spec omits the feature entirely. Dynamic entity creation cannot be specified without an empirical probe. PRD will carry this FR as conditional on a discovery spike, with the schema-open requirement (unconditional) separated from entity creation (conditional). Flagged to Jensen at finalize.
